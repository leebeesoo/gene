## 핵심 진단
1. 상세 화면이 검색에 안 잡힌다: `#/…`, `?y=`, `?n=` 상세 화면은 검색엔진이 한 페이지로 본다. 상세 페이지를 진짜 HTML로 만들어야 한다(약 5,700쪽 가능).
2. 대표 주소가 죽은 주소: 28개 파일의 canonical·og:url이 `leebeesoo.github.io/gene/`. 도메인 연결 날 일괄 교체.
3. 기본이 없다: robots.txt, sitemap, 네이버·구글·다음 소유 확인, 일부 H1, 서비스별·결과별 공유 이미지.
4. 내부 문서가 공개됨: `docs/`, `tools/`, `tests/`가 사이트로 서빙 중 → 빌드 결과물(`dist/`)만 배포.
5. 이길 수 있는 검색어는 긴 검색어: "○○구 로또 명당", "1994년생 나이 띠", "1988년 100원 가치", "쥐띠 소띠 궁합", "김해 김씨 시조", "여수 전어구이 제철", "굴 제철 언제". 큰 검색어("만 나이 계산기", "여수 맛집")는 포털이 직접 답하거나 플레이스가 가져감.

## 실행 순서
### 1단계 (도메인 정해지면 바로, 약 2일)
- 전 사이트 canonical·og:url·JSON-LD url을 새 도메인으로 교체
- robots.txt, sitemap index + 서비스별 sitemap, 네이버 서치어드바이저·구글 서치콘솔·다음 웹마스터도구 등록용 확인 태그
- 허브·10개 서비스 첫 화면 타이틀·설명·H1·OG 교체(문서의 "제안" 문구), 빠진 og:image 추가, 파일명에 버전(og.v2.jpg)
- 근본 테스트·제철식당·맛남의 광장 첫 화면에 정적 본문(H1·소개·FAQ) 넣기
- Cloudflare 빌드 명령 `node tools/seo/build.mjs`, 출력 `dist/` (내부 문서 비공개)

### 2단계 (정적 페이지 생성, 약 1~2주)
`tools/seo/build.mjs` 하나가 데이터에서 페이지를 만든다. 내용 250자 미만 페이지는 만들지 않는다(빈약 페이지 방지).
- 명당로드: 회차 1,249 + 다음 회차, 시도 17·시군구 233(1등 3건 미만은 noindex), 2회 이상 1등 판매점 1,939, 번호 45, 안내 3
- 나때연감: 연도 76 + 나이표(매년 1/1 갱신, 12월 초 다음 해 미리)
- 남은봄: 만 나이·살아온 날·기대수명표·정신 나이 페이지 분리
- 근본·이름: 유형 16, 본관 78, 성씨 131, 인기 이름 약 400, 띠 궁합 78 + 띠 12
- 먹거리: 제철식당 지역 161 + 지역×메뉴 582(식당 3곳 이상) + 재료 206, 제철장보기 품목 62 + 월 12, 맛남의 광장 신호 품목·시도
- 페이지마다 공유 이미지 자동 생성(1200×630), 이미지 사이트맵, 예전 `#` 링크는 새 주소로 자동 이동

### 3단계 (공유·재방문)
- 카카오 공유(SDK, 무료·앱 키 필요), 인스타 스토리용 9:16 결과 카드, "친구와 비교" 링크
- 명당로드 토요일 21:10·일요일 09:10 자동 갱신(출시 때 켬)
- 시즌 캠페인: 수능, 연말 결산, 설·추석, 벚꽃, 매주 로또

## 참고
- 구글은 2026-05-07부터 FAQ 리치 결과를 보여주지 않지만, FAQ 본문은 AI 검색(네이버 AI 브리핑·구글 AI 개요·ChatGPT) 인용에 여전히 유리하므로 넣는다.

- 검색량은 키워드 도구 로그인 없이 자동완성·상위 사이트로 추정했다. 서치어드바이저·서치콘솔 연결 후 실제 수치로 다시 고른다.
