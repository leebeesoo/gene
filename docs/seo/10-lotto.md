## 2. 벤치마킹

- **동행복권** (`dhlottery.co.kr/lt645/result`, `/wnprchsplcsrch/home`): 1차 출처다. 회차는 쿼리나 폼으로 바뀌어서 회차마다 색인되는 URL이 약하다. 그래서 "1250회 당첨번호" 검색은 언론사와 통계 사이트가 차지한다.
- **펴늬** `pyony.com/lotto/rounds/1249/`: 회차마다 정적 URL을 만든다. title은 "로또 1249회 당첨번호 확인. 당첨자수, 당첨금, 1등 판매점 바로 확인."이다. 페이지 안에 번호, 1~5등 당첨금 표, 1등 판매점 표(자동·수동, 주소), 다음 추첨 D-day, 세후 계산기 링크(`/lotto/calculator/?q=금액`), 카톡·밴드·네이버 공유가 있다. **다음 회차 페이지 `/rounds/1250/`을 미리 만들어 두고** 결과를 기다린다(색인 선점). 약점: 판매점은 `/win-stores/{id}/map/` 지도뿐이고, **지역별 URL이 없다**.
- **언론사 "로또 당첨번호조회-1239회"** (광주매일 등, 다음 뉴스): 추첨 31분 뒤에 올라온다. 번호, 홀짝, 합계, 구간별 개수, 1~5등 당첨자, 지역별 1등 판매점 목록을 한 번에 담는다. 매주 같은 틀로 찍어 내서 신선도로 이긴다.
- **명당 기사·블로그** (위키트리 "1등 48번 명당", 경향 "노원구 스파 18번", dnublog "전국 로또 명당 TOP10"): 순위 TOP10에 지도 링크를 붙이는 수준이다. 집계 시점이 기사마다 달라 숫자가 서로 다르다. 우리는 공식 회차 자료로 직접 셌다(스파 53회, 부일카서비스 50회, 1249회까지). 이게 차별점이다.
- **앱** (로또즈, 로또랩스, 마이로또): 출현·미출현 통계와 생성기를 앱 안에 둔다. 웹 색인이 거의 없어서 "로또 7번 출현 횟수" 같은 웹 롱테일은 비어 있다.

**빈자리**: 언론과 펴늬는 "○○구 로또 명당", "○○시 1등 판매점 순위" 같은 **시군구 단위 랭킹 페이지**를 만들지 않는다. 우리 데이터에서 233개 시군구 가운데 164곳이 1등 10건 이상이라, 바로 내용이 차는 페이지를 만들 수 있다.

## 4. 쉽게 보이고 흥미롭게 보이는 것

1. **토요일 카운트다운 훅**: 모든 정적 페이지 상단에 "제{N}회 추첨까지 1일 03:12 · 판매 마감 토 20:00"를 둔다. 추첨이 끝나면 같은 자리를 "방금 나온 {N}회 번호"로 바꾼다. 매주 다시 찾아올 이유가 된다.
2. **"오늘의 번호" 카드(1080×1350)**: 이미 캔버스로 만든다. 카드 하단에 회차, 날짜, `{D}/lotto`를 크게 넣는다. 일요일에는 "내 번호 vs {N}회 결과" 맞힌 개수 카드를 만든다("3개 맞음, 5등!"). 이게 자랑하고 공유하고 싶어지는 지점이다.
3. **동네 명당 카드**: 시군구 페이지마다 OG 이미지를 만든다(지역 이름, 1등 {n}건, 1위 판매점). 카톡 미리보기에 "노원구 1등 247건"처럼 숫자가 바로 보이게 한다.
4. **회차 OG 이미지**: 번호 공 6개 + 보너스, "1등 {k}명 · {금액}". 빌드 때 SVG에서 PNG로 만든다(resvg, 무료).
5. **링크 비교**: "친구 번호랑 내 번호 겹친 개수"는 이미 `?s=` 공유가 있다. 공유 링크의 canonical은 `/lotto/`로 고정한다.
6. **커뮤니티 시드**: 일요일 아침에 네이버 블로그나 카페용 짧은 요약("{N}회 1등 {k}곳 중 {시도} {x}곳")과 해당 회차 URL을 올린다. 지식iN의 "○○ 로또 명당 어디?" 질문에는 시군구 페이지로 답한다.
