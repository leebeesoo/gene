## 2. 벤치마킹

- **16Personalities**: 유형마다 정적 페이지(`/ko/성격유형-intj`)가 있고, 유형별 OG 이미지를 버전 쿼리를 붙여 쓴다(`/static/images/social/intj.png?v=3`). 결과를 공유하면 미리보기에 그 유형이 보인다. 근본 테스트의 16개 코드가 그대로 따라 할 수 있는 구조다.
- **방구석연구소**(banggooso.com/ko): Kakao JS SDK 2.7.2를 쓰고, 테스트마다 공유 이미지를 따로 둔다(`banggooso_share_img_500_ko.jpg`). 카톡 메시지에 "나도 해보기" 버튼을 다는 것이 바이럴 루프의 핵심이다.
- **케이테스트**: 테스트 하나에 결과 페이지가 여러 개 있다. 결과를 공유하면 친구는 "나도 테스트하기"로 들어온다. 본문은 JS로 그려서 미리보기 메타만 공유 품질을 결정한다.
- **Spotify Wrapped**: 9:16 카드 여러 장을 순서대로 보여 주고, 장마다 숫자 하나만 크게 쓴다. 사람들은 인스타 스토리에 그대로 올린다. 연말 한정이라 희소성이 생긴다.
- **토스 '오늘의 ○○'·당근 '동네 소식'**: 매일 또는 동네마다 바뀌는 작은 숫자 하나가 다시 들어올 이유가 된다. 우리 허브에는 이미 "오늘의 공·오늘의 코드"가 있지만, 그 화면을 공유할 수는 없다.

**카카오 규칙** (devtalk.kakao.com 스크랩 체크리스트·FAQ 기준)

- 링크 미리보기는 서버 HTML의 `og:*`만 읽는다. JS로 넣은 태그와 해시(`#…`)는 반영되지 않는다.
- 이미지는 JPG/PNG만 된다(WebP 불가). 800×400(2:1)에 최적화되어 있고, 1:1·2:1·4:3을 벗어나면 자동으로 잘린다. 그래서 1200×630으로 만들되 핵심 글자는 가운데 1200×600 안쪽, 좌우 여백 80px 안에 둔다.
- 미리보기 캐시는 공유 디버거로 메타만 지울 수 있고, 썸네일은 남는다. 이미지를 바꾸려면 **파일 이름을 바꿔야** 한다. 우리 `_headers`가 `*.png`를 1년 immutable로 캐시하므로, 덮어쓰기는 두 겹으로 막혀 있다.
- `og:url`이 실제 주소와 다르면 카카오는 `og:url` 쪽을 다시 읽는다. 주소 끝 `/` 유무도 캐시를 따로 잡는다.
- **Kakao JS SDK `Kakao.Share`**: 쿼터 안에서는 무료다. 문서에는 30,000건으로 나오는데 일 단위인지 월 단위인지는 표기가 엇갈려 콘솔에서 확인해야 한다. 앱 등록, JavaScript 키, "JavaScript SDK 도메인"과 "제품 링크 웹 도메인" 등록이 필요하다. 이렇게 하면 버튼 2개, 결과별 이미지, 제목·설명을 메시지마다 다르게 보낼 수 있다. `Kakao.Share.uploadImage`로 캔버스 결과 이미지를 카카오 서버에 올리면 우리 서버 없이도 개인화 썸네일을 쓸 수 있다(보관 기간 제한 있음, 문서 확인 필요). 짧은 시간에 반복해서 공유하면 일시 제한된다.

## 3. 우리 사이트 진단 (공유·허브)

**공통 문제**

- canonical·og:url이 모두 `https://leebeesoo.github.io/gene/…`인데, 배포처는 Cloudflare Pages다(DEPLOY.md). 실제 도메인이 정해지면 전부 바꿔야 한다. 그대로 두면 카톡이 GitHub Pages 쪽 메타를 읽는다.
- 루트에 `robots.txt`와 `sitemap.xml`이 없다.
- 어떤 서비스도 결과 상태를 OG에 반영하지 못한다. `?n=`, `?y=`, `?s=`, `?invite=`, `#g=`는 화면만 바꾸고, 미리보기는 항상 서비스 대표 이미지 하나다.
- 공유 카드가 모두 1080×1350(4:5)이다(명당로드만 1080×1080). 9:16 스토리용과 1200×630 링크용은 없다.
- 카카오 SDK는 어디에도 없다. 모두 Web Share → 링크 복사 → 이미지 저장 순서로 대체한다. 데스크톱 카톡 PC에서는 "링크 복사"만 남는다.

**서비스별 현황**

| 서비스 | og:image | 공유 카드 | 공유 URL에 담기는 상태 | 친구와 비교 |
|---|---|---|---|---|
| 허브 `/` | **없음** (twitter·JSON-LD도 없음) | 없음 | `#fun` 등 필터만 | 없음 |
| 오늘로또 | lotto/og.png | 1080×1350, 시트에 저장·복사·공유 | `?s=&e=&r=` → "친구가 보낸 행운 번호" 화면 | 없음 (받은 쪽 번호만 보임) |

**허브 발견성**

- 타일 10개는 모두 `<a href="lotto/">` 같은 실제 링크라 크롤러가 따라갈 수 있다. 장점이다.
- H1은 화면에 안 보이는 `.sr`이고, "오늘 바뀐 것" 숫자는 JS로 계산한다. 크롤러가 보는 원본 HTML에는 날짜 없는 "오늘의 재미판"만 있다.
- 신선도 신호(dateModified, 정적 날짜 텍스트)가 없다.
- 하단 링크는 소개 2개뿐이다. 서비스 내부 대표 페이지(예: 근본 코드 16종, 1990년생 연감)로 들어가는 직행 링크가 없다.

## 4. 쉽게 보이고 흥미롭게 보이는 것

**이미지 세 가지 규격** (모든 서비스 공통)

- **링크용 1200×630 JPG**: 카톡, 스레드, X, 네이버 미리보기에 쓴다. 바탕은 사이트 bg, 왼쪽 위에 서비스 이름(700, 40px), 가운데에 숫자나 결과 한 줄(700, 96~120px), 그 아래 한 줄 질문(500, 40px, muted), 오른쪽 아래에 포인트 색 점과 "재미랩"을 둔다. 글자는 가운데 1040×520 안에 넣는다.
- **스토리용 1080×1920 PNG**: 위 250px과 아래 340px은 인스타 UI 자리라 비운다. 핵심 숫자는 y 600~1100에 둔다. y 1450 근처에 "링크 스티커 붙이는 자리" 빈칸(점선 없이 여백만)을 둔다.
- **피드용 1080×1350**: 지금 있는 카드를 유지한다.

**매일·매주 다시 올 이유**

- 오늘로또: 금요일 "이번 주 번호 뽑았어요?", 토요일 20:35 이후 "당첨 확인".
- 명당로드: 일요일 "이번 주 1등 나온 곳".
- 근본 테스트: "오늘의 코드"(허브).
- 이름레이더: "오늘의 이름"(매일 이름 하나와 그 인원).
- 나때연감: "오늘, ○년 전 이날".
- 남은봄: 월요일 "올해 남은 주말 N번".
- 제철장보기: 매달 1일 "이달 제철", 목요일 "이번 주 싸진 것".
- 맛남의 광장: 주간 "이번 주 남는 것".

**커뮤니티·블로그·쇼츠 규칙** (일반 관행이다. 올리기 전에 게시판 공지를 반드시 확인한다)

- 더쿠·에펨: 직접 홍보는 차단 대상이다. 결과 이미지 자체를 내용으로 올리고 링크는 달라는 댓글이 있을 때만 단다.
- 인스티즈·네이트판: 테스트 결과 공유 글이 많이 올라온다. 제목은 "○○ 나왔는데 다들 뭐 나옴?" 형태가 반응이 좋다.
- 디시: 로또 관련 갤러리에는 명당 지도나 통계 이미지를 올린다. 여러 계정 동원과 도배는 금지한다.
- 네이버 블로그·카페 후기: 대가를 주는 후기에는 공정위 추천·보증 심사지침에 따라 맨 위에 "광고"나 "협찬"을 표시한다.
- 유튜브 쇼츠: 1080×1920으로 15~30초 화면 녹화 시리즈를 만든다(예: "1990년생이 태어난 해 물가").

  - 기존 GitHub Actions(`surplus-data.yml`과 같은 방식)에서 Node 스크립트를 돌린다. `satori`와 `@resvg/resvg-js`(서버·브라우저 없이 Pretendard OFL 폰트 파일 사용)로 만들거나, 템플릿 HTML을 Playwright로 캡처한다.
  - 결과물은 `/og/{서비스}/{slug}.{hash8}.jpg`(150KB 안팎)이고, 해당 정적 HTML 페이지의 og:image에 박는다.
  - 공유 URL은 이 정적 페이지를 가리키게 하고(`?invite=` 등 기존 쿼리는 그대로 붙임), 페이지 본문의 "나도 해보기"로 앱에 들어오게 한다.
- **대상과 페이지 수**
  - 근본 코드 `/roots/code/{code}/`: 16개
  - 나때연감 `/birthyear/{yyyy}/`: 76개
  - 명당로드 `/lottomap/region/{sido}/`: 17개
  - 오늘로또 `/lotto/round/{n}/`: 매주 1개, Action이 갱신
  - 이름레이더 성씨 `/names/surname/{성}/`: 상위 100개
  - 제철장보기 품목 `/season/item/{id}/`: 약 62개
  - 합계 약 280장
- **Kakao SDK**
  - 공유 버튼을 누를 때만 SDK를 지연 로드하고 `Kakao.Share.sendDefault`(feed)를 쓴다.
  - 버튼은 [결과 보기] [나도 해보기] 두 개다.
  - 결과 카드는 `uploadImage`로 올려 imageUrl로 쓴다.
  - SDK가 실패하면 지금처럼 Web Share로 넘어간다.
- **9:16 스토리 카드**를 각 서비스 공유 시트에 "스토리용" 탭으로 추가한다.
- **비교 링크**
  - 이름레이더 `?n={a}&vs={b}`
  - 나때연감 `?y={a}&vs={b}`
  - 남은봄 `?by={출생연도}&s={성별}`(연도만, 날짜는 넣지 않음)
  - 명당로드 `?r={sido}`
  - 오늘로또는 받은 번호와 내 번호에서 "겹친 수 {k}개"를 보여 준다.
