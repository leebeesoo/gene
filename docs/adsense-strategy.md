**한 줄 결론:** 재미랩은 "도구만 있고 글이 적은 새 사이트"라서 거절 1순위가 **가치가 낮은 콘텐츠**입니다. 신청 전에 ① 사이트 전체용 소개·문의·개인정보처리방침을 루트에 만들고 ② 각 서비스 첫 화면에 사람이 쓴 설명 글(쓰는 법, 계산 근거, 데이터 출처, 주의사항)을 붙이고 ③ 빈 광고 칸·자리표시 ID가 화면에 보이지 않게 정리한 뒤, ④ 진짜 게시자 ID를 `<head>` 코드와 `ads.txt`에 넣고 **"애드센스 코드 스니펫"** 방식으로 확인하고 검토를 요청하세요.

## 1) 신청 절차 (현재 화면 기준)

### 1-1. 계정 만들기
1. **[공식]** `https://adsense.google.com` 에서 "애드센스 가입"으로 시작합니다. 만 18세 이상이어야 하고, 사이트 HTML을 직접 고칠 수 있어야 합니다.
2. **[공식]** 가입 후 홈 화면에서 할 일 3가지: **결제 정보 입력**, (선택) 광고 미리보기, **사이트 연결**. 결제 정보는 심사 중에 미리 넣어 두라고 공식 문서가 권합니다(안 넣으면 지연).
3. **[공식]** 2026년 6월부터 광고 게재·지급 전에 **신원 확인**(정부 발급 사진 신분증, 지역에 따라 셀카 영상)을 요구할 수 있습니다. 2026년 9월 업계 보도(Search Engine Roundtable)에 따르면 신원 확인 기준 금액이 $0으로 내려가 수익이 생기기 전에 확인을 요구받게 됩니다. 요청받으면 45일 안에 끝내야 합니다. **결제 프로필 이름을 신분증 이름과 똑같이** 쓰세요.
4. **[공식]** 한 사람당 애드센스 계정은 하나입니다. 예전에 만든 계정이 있으면 새로 만들지 말고 그 계정을 쓰세요(중복 계정은 거절 사유).
5. **[후기]** 거절 메일에 사유가 없으면 결제 프로필 주소 문제일 수 있다는 글이 있습니다(월급쟁이부자들 커뮤니티, 2026-02). 주소는 동·호수까지 실제 주소로 정확히 쓰세요.

### 1-2. 사이트 추가 → 연결 → 검토 요청 (화면 메뉴명 그대로)
**[공식]** 두 가지 길이 있고 결과는 같습니다.

- **홈 화면에서:** 홈 → **사이트 추가** → URL 입력 → **저장** → "**애드센스에 사이트 연결**" 카드에서 **시작**
- **사이트 메뉴에서:** 왼쪽 **사이트** → **+ 새 사이트** → URL 입력 → **저장** (상태가 "**검토 필요**"로 들어감)

이어서:
1. 확인 방법 3가지 중 하나 선택: **애드센스 코드 스니펫** / **ads.txt 코드 스니펫** / **메타 태그**
2. 코드를 사이트에 넣고 배포 → "작업을 마쳤다"는 **체크박스** 선택 → **확인**
3. **검토 요청** 클릭
4. (선택) 동의 관리 플랫폼(CMP) 고르고 **제출**. 유럽(EEA·영국·스위스) 방문자용입니다. 한국 대상 사이트라도 "Google의 CMP"를 켜 두면 손해는 없습니다. **[판단]**
5. 결과 확인: 홈의 **사이트** 카드 또는 사이트 메뉴의 상태. 공식 영문 상태는 **Getting ready** → **Ready** 또는 **Needs attention** 입니다. 한국어 도움말에서 확인한 이름은 "**검토 필요**"(추가 직후)와 "**준비됨**"이며, 나머지 한국어 표기는 화면마다 조금 다를 수 있습니다.

URL은 **`jaemilab.net`(도메인만)** 입력합니다. `/lotto/` 같은 경로는 넣지 않습니다. 애드센스는 도메인 단위로 사이트 전체를 심사합니다. **[공식: 사이트 전체를 정책 기준으로 검토]**

**검토 기간 [공식]:** 보통 며칠, 경우에 따라 **2~4주**. 코드가 방문이 거의 없는 페이지에만 있으면 오래 걸릴 수 있다고 공식 문서에 적혀 있습니다. 또 **사이트를 삭제했다가 다시 넣지 말라**(지연됨)고 공식 문서가 경고합니다.

### 1-3. 확인 방법 3가지 중 무엇을 고를까
| 방법 | 넣는 곳 | 장점 | 단점 |
|---|---|---|---|
| 애드센스 코드 스니펫 | 모든 페이지 `<head>` | 바로 읽힘. 승인 뒤 그대로 광고에 쓰임 | 승인 전에도 스크립트가 로드됨(광고는 안 나옴) |
| ads.txt 코드 스니펫 | 루트 `/ads.txt` | 페이지를 안 고쳐도 됨 | **[공식]** 반영에 며칠, 요청이 적은 사이트는 최대 한 달까지 걸릴 수 있음 |
| 메타 태그 `<meta name="google-adsense-account" content="ca-pub-…">` | `<head>` | 광고 스크립트 없이 소유만 확인 | 승인 뒤 스크립트를 따로 넣어야 함 |

**[판단] 추천: "애드센스 코드 스니펫"을 고르세요.** 우리 사이트는 이미 133개 HTML의 `<head>`에 스크립트 자리가 있으니 `ca-pub-XXXXXXXXXXXXXXXX`만 진짜 번호로 바꾸면 됩니다. **동시에 `ads.txt`도 진짜 번호로 바꿉니다.** ads.txt는 확인 방법으로 고르지 않더라도 **[공식]** "필수는 아니지만 강력 권장"이고, 승인 뒤 "승인되지 않음(Unauthorized)" 경고를 막아 줍니다. 원하면 메타 태그도 같이 넣어 둘 수 있습니다(둘 다 있어도 문제 없음).

ads.txt 최종 형태 (pub 번호만 본인 것):
```
google.com, pub-1234567890123456, DIRECT, f08c47fec0942fa0
```

## 2) 심사 기준 (공식 문서에 적힌 것만)

- **자격:** 만 18세 이상. 직접 소유하고 HTML을 고칠 수 있는 사이트. 프로그램 정책 준수. 콘텐츠는 "고품질이고 독창적이며 방문자를 끌어야" 합니다(원문: "high-quality, original, and attract an audience").
- **충분한 텍스트:** "페이지에 충분한 텍스트가 있는지 확인하라", 완전한 문장과 문단을 쓰고, 템플릿 상태로 내지 말고 완성된 사이트를 내라.
- **자동 생성이나 얇은 페이지 금지:** 자동 생성 페이지, 독창적인 내용이 거의 없는 페이지에 코드를 넣지 말 것. 광고 코드만 있는 빈 테스트 페이지는 승인되지 않습니다.
- **탐색(내비게이션):** 명확한 메뉴. 리디렉션, 로그인 뒤에 숨은 페이지, 깨진 링크, 과도한 팝업, 미완성 페이지가 없어야 합니다.
- **접근 가능:** 공개 상태로 열려야 합니다. 로그인 벽 금지, robots.txt가 애드센스 크롤러를 막지 않을 것, 정식 SSL(자체 서명 금지), HTTP→HTTPS 리디렉션. 크롤러 이름은 **Mediapartners-Google**와 **Google-Display-Ads-Bot**입니다.
- **광고 게재 불가 화면 (게시자 정책 "콘텐츠가 없는 화면의 Google 광고"):** 게시자 콘텐츠가 없거나 가치가 낮은 화면, **제작 중(under construction)** 화면, 알림·탐색용 화면, 감사·종료·오류 같은 "막다른" 화면, 사람이 검토하지 않은 자동 생성 콘텐츠.
- **사용자 제작 콘텐츠(UGC):** 댓글 같은 UGC도 모든 정책을 적용받고 **관리 책임은 게시자**에게 있습니다. 위반이 있으면 해당 페이지, 심하면 사이트 전체 광고가 제거됩니다.
- **지원 언어:** 한국어는 지원 언어입니다.
- **공식 문서에 없는 것:** 최소 글 수, 최소 글자 수, 도메인 나이, 방문자 수. 공식 자격 요건 페이지에는 이런 기준이 없습니다.

## 3) 흔한 거절 사유와 해결

### 3-1. 공식 문서가 밝힌 사유 ("사이트가 광고를 게재할 준비가 되지 않음" 등)
| 사유 | 원인 | 해결 |
|---|---|---|
| **코드 누락이나 불완전** | 코드가 `<head>`에 없음, 신청한 사이트와 다른 곳에 넣음 | 신청한 도메인의 `<head>`에 넣고 배포 확인 |
| **사이트 다운 또는 사용할 수 없음** | URL 오타, 로그인 보호, robots.txt 차단, 잘못된 SSL | URL이 틀렸으면 지우고 다시 추가(이 경우만), 로그인 해제, robots.txt 확인, 정식 SSL과 HTTPS 리디렉션 |
| **가치가 낮은 콘텐츠** (콘텐츠 부족이나 나쁜 사용자 경험) | 가치 있는 내용, 좋은 사용 경험, 탐색 요소가 부족 | 페이지마다 독창적인 텍스트, 메뉴, 미완성 페이지 제거. 공식 문서는 구체 숫자를 주지 않음 |
| **정책 위반** | 프로그램 정책 위반 콘텐츠 | 정책 센터에서 확인하고 고친 뒤 검토 요청 |
| 중복 계정 / 트래픽 출처 / 미지원 언어 | 계정 2개, 유료 클릭 트래픽 등 | 해당 사항 정리 |
| 설정 미완료 | 결제 정보 등 필수 설정을 안 끝내고 검토 요청 | **[공식]** 설정 작업을 안 끝내면 "준비 중"에 머물고 검토되지 않음 |

### 3-2. 국내 후기에서 반복되는 사유와 해결 [후기, 검증 안 됨]
- **"가치 없는 콘텐츠(가없콘)"가 가장 흔하다**, 범용 거절 코드처럼 쓰인다(월급쟁이부자들, 2026-02 / tilnote, 2026-05). 해결: 글 개수보다 **직접 경험, 자기 데이터, 분석**을 더해 차별화하기. AI 초안은 사람이 고쳐 쓰기.
- **필수 페이지 누락:** 소개, 문의, 개인정보처리방침, (이용약관)을 메뉴나 푸터에서 바로 찾게 하라(tilnote 2026-05, 메일리 「창문밖」 2026-07).
- **주제 산만:** 한 주제로 묶어야 정체성이 분명하다(메일리 2026-07, 브런치 「친절한효자손」 2026-07).
- **구조:** 카테고리를 나누고 내부 링크, 홈 > 카테고리 > 글 경로(breadcrumb)를 만들라(월급쟁이부자들 2026-02).
- **접속 문제:** 심사 중 다운, robots.txt 전체 차단, 로그아웃 상태에서 안 보임, 신청 URL과 실제 주소가 다름(크몽 칼럼 요약). Cloudflare에서 **루트 도메인은 안 열리고 www만 열려** 문제가 된 사례(인프런 Q&A).
- **도메인 나이:** 30일 미만 새 도메인은 추가 심사를 받는다며 사이트맵 제출 뒤 한 달쯤 색인을 쌓고 신청하라는 글이 있음(tilnote 2026-05). **공식 근거는 없습니다.**
- **숫자 기준(글 20~50개, 1,000자, 800단어 등):** 글마다 제각각입니다. 블로그용 기준이라 도구 사이트에 그대로 맞지 않습니다.
- **"2026년 들어 승인이 어려워졌다":** 여러 글이 이렇게 말하지만 출처가 없습니다.
- **재신청 간격:** 고치고 15~30일 뒤 재신청하라는 글(tilnote). 공식 문서에는 대기 기간이 없습니다.

### 3-3. Cloudflare 관련 [판단 + 비공식 자료]
Cloudflare **Bot Fight Mode**나 "AI 봇 차단" 설정이 Google 광고 크롤러에 챌린지를 걸 수 있다는 보고가 여럿 있습니다(업체 블로그와 포럼이며 Cloudflare나 Google 공식 확인은 없음). 2026-11-14에 이 환경에서 `Mediapartners-Google`과 `Google-Display-Ads-Bot` UA로 `https://jaemilab.net/`에 요청했을 때 **200 응답**이 왔습니다. 다만 Google 실제 IP에서 보는 결과와 다를 수 있습니다. 심사 기간에는 Cloudflare **보안 → 이벤트**에서 이 두 UA가 막힌 기록이 없는지 확인하세요.

1. **루트에 사이트 전체용 페이지 3개 만들기:** `/about.html`(재미랩이 무엇인지, 누가 왜 만드는지, 14개 서비스 소개, 데이터 출처 원칙, 업데이트 방식), `/contact.html`(이메일, 응답 기간), `/privacy.html`(GA4·애드센스 쿠키, 맞춤 광고, 서비스별 처리방침 링크 모음). 원하면 `/terms.html`도. 허브 머리말이나 푸터와 **모든 서비스 공통 푸터**에서 링크. **[후기에서 반복 + 공식 "탐색 요소"]**
2. **서비스마다 사람이 쓴 설명 글 붙이기** (도구 사이트에서 가장 중요한 항목). 각 서비스 첫 화면이나 결과 아래에 "이게 뭔가요 / 어떻게 계산하나요(근거, 공식) / 데이터 출처와 기준일 / 결과 읽는 법 / 주의사항 / 자주 묻는 질문"을 완전한 문장으로 쓰기. 계산기는 계산식과 예시, 지도는 데이터 출처와 갱신 주기, 사주와 궁합은 "재미용, 과학적 근거 없음"을 분명히. **[공식 "충분한 텍스트, 완전한 문장" + 판단]**
   - 목표 기준은 공식 숫자가 없으므로 **[판단]** "도구를 안 쓰고 글만 읽어도 배울 게 있는 페이지"로 잡으세요. 결과가 JS로만 그려지는 페이지는 크롤러에게 빈 페이지로 보일 수 있으니 설명은 **HTML에 직접** 쓰세요.
3. **빈 광고 칸이 보이지 않게 하기:** 승인 전에는 광고가 채워지지 않습니다. 280px짜리 "광고" 라벨 빈 상자가 크롤러나 심사자에게 보이면 "미완성, 제작 중"처럼 보일 수 있습니다. **[판단]** 권장 방법은 둘 중 하나입니다.
   - (권장) 승인 전에는 `<head>` 스크립트만 진짜 ID로 넣고, `<ins>` 광고 칸 마크업은 **아예 빼거나 기본값을 `display:none`**(채워졌을 때만 보이게)으로 뒤집기. 승인 후 광고 단위를 만들고 진짜 slot ID로 다시 켜기.
   - `<ins>`에 `ca-pub-XXXX` / `0000000000` 같은 가짜 값을 남겨 두지 않기(스크립트 ID와 안 맞는 잘못된 광고 요청이 생김).
4. **`<head>` 스크립트와 `ads.txt`를 진짜 게시자 ID로 동시에 교체 → 배포 → `https://jaemilab.net/ads.txt`가 브라우저에서 열리는지 확인** → 애드센스에서 "애드센스 코드 스니펫"으로 **확인** → **검토 요청**.
5. **"준비 중", 빈 결과, 깨진 링크 0개:** 현재 HTML에서 "준비 중"이라는 문구는 찾지 못했습니다. 데이터가 비어 있을 때 나오는 화면(지도 0건, 가격 없음 등)도 안내 문장이 나오게 하고, 모든 내부 링크와 sitemap URL이 200인지 점검하세요. **[공식 "깨진 링크, 미완성 페이지"]**
6. **탐색:** 모든 서비스 페이지에 허브로 돌아가는 링크와 공통 푸터(소개, 문의, 개인정보, 다른 서비스). 서비스 안 하위 페이지끼리 내부 링크. **[공식]**
7. **sitemap과 Search Console:** `sitemap.xml`(색인 파일)을 Search Console에 제출하고, 주요 페이지가 색인되는지 확인. 색인이 애드센스 공식 조건은 아니지만 크롤러가 페이지를 찾는 데 도움이 됩니다. **[판단]**
8. **속마음 칠판(익명 UGC):** 공식 문서상 UGC 관리 책임은 게시자에게 있고, 심사는 사이트 전체를 봅니다. 광고를 안 단 페이지라도 혐오나 음란 글이 떠 있으면 위험합니다. **[판단]**
   - 신청 전에 금칙어 필터, 신고 버튼, 운영 원칙 안내가 실제로 작동하는지 확인.
   - 심사 기간에는 **허브와 다른 서비스에서 칠판으로 가는 링크를 잠시 빼는 것**이 가장 안전합니다. `noindex`는 검색 노출만 막을 뿐 애드센스 크롤러 방문을 막는다는 공식 근거는 없습니다. 이미 robots.txt에서 `/donkey/live`는 막혀 있습니다.
9. **글이 아주 적은 페이지:** 설명을 보강할 수 없는 얇은 페이지(결과만 나오는 하위 페이지 등)는 승인 전까지 **허브 메뉴와 sitemap에서 빼거나** 내용을 채운 뒤 노출하세요. 페이지 수보다 페이지 하나하나의 완성도가 중요합니다. **[공식 "얇은 페이지에 코드 넣지 말 것" + 판단]**
10. **YMYL(돈, 건강) 페이지:** 청약, 이자, 예금자보호, 사기 체크, 시니어 검진 달력은 **출처(법령, 공공기관 링크), 기준일, "참고용이며 최종 확인은 해당 기관에서"** 문구, 운영자 정보를 꼭 넣으세요. "YMYL"은 Google 검색 품질 평가 개념이고 애드센스 공식 심사 항목으로 적혀 있지는 않습니다. 다만 신뢰도와 오정보 위험을 줄이는 데 필요합니다. **[판단]**
11. **로또 관련:** 게시자 제한 정책의 "온라인 도박"은 온라인 복권 **구매**나 베팅을 가능하게 하는 콘텐츠를 말하며, 승인 거절이 아니라 **광고 수요 제한** 사유입니다. **[공식]** 우리 로또 서비스는 구매 기능이 없으니 해당하지 않을 가능성이 높습니다. 다만 "구매하러 가기" 같은 판매 유도 문구나 링크는 넣지 마세요. 19세 안내와 "재미용, 당첨과 무관" 문구는 유지하세요. **[판단]**
12. **사이트 나이:** 공식 기준은 없습니다. **[공식 문서에 없음]** "30일 기다려라"는 후기 의견입니다. **[판단]** 1~11번을 끝내고, Search Console에서 주요 페이지 색인이 확인되면(보통 1~3주) 신청하는 것을 권합니다. 오늘 바로 신청하는 것보다 첫 시도 성공률이 높습니다.
13. **기타:** `www.jaemilab.net`도 DNS를 추가해 루트로 301 리디렉션(사람이 www로 쳐도 열리게). 심사 중에는 큰 구조 변경이나 장시간 배포 중단을 피하기. 팝업이나 전면 안내는 최소화. 결제 정보 미리 입력.

## 5) 거절되면 할 일
1. **[공식]** 애드센스에 로그인하거나 메일을 열어 **정확한 사유**를 확인합니다. 사이트 메뉴 상태가 "조치 필요"면 안내 링크를 따라갑니다.
2. 사유별 처리:
   - **사이트 다운 또는 사용할 수 없음:** 로그아웃·시크릿 창에서 `https://jaemilab.net/` 열기, robots.txt, Cloudflare 보안 이벤트(Bot Fight Mode, WAF), SSL, 신청 URL 철자 확인. URL이 틀린 경우에만 사이트를 지우고 다시 추가합니다. **[공식 + 판단]**
   - **가치가 낮은 콘텐츠:** 4장의 1·2·9번을 더 강하게. 설명 글 보강, 얇은 페이지 정리, 칠판 링크 제거, 전체 공통 메뉴와 푸터. 페이지를 늘리기보다 기존 페이지를 깊게. **[후기 공통 + 판단]**
   - **정책 위반:** **정책 센터**에서 해당 URL과 항목을 보고 수정합니다. **[공식]**
   - **사유가 없거나 모호함:** 결제 프로필(이름, 주소, 전화) 정확성부터 확인. **[후기]**
3. **[공식]** 고친 뒤 **사이트** → 해당 사이트 → 코드가 있는지 확인 → **다음** → **검토 요청**. 공식 대기 기간은 없습니다. **[판단]** 실제로 고친 내용이 크롤링될 시간을 주기 위해 **1~2주 뒤** 재요청을 권합니다(후기는 15~30일). 고친 것 없이 바로 다시 누르지 마세요.

## 6) 승인 후 할 일
1. **광고 단위 만들기 [공식 메뉴 기준, 세부는 `docs/adsense-setup.md` 참고]:** 광고 → 광고 단위 기준 → 디스플레이(반응형), 인피드, 멀티플렉스 → 받은 slot ID로 `data-ad-slot="0000000000"`과 `<ins>`의 `data-ad-client`를 교체하고 광고 칸을 다시 켜기.
2. **ads.txt 상태**가 사이트 메뉴에서 "승인됨"인지 확인. "찾을 수 없음"이나 "승인되지 않음"이면 파일과 번호를 고치고 **업데이트 확인**. **[공식]**
3. **광고를 넣지 말 곳 [공식 게시자 정책]:** 오류·감사·빈 결과 화면, 문항 진행 중 화면처럼 콘텐츠가 없는 화면, UGC 칠판(현재 방침 유지). 광고가 본문보다 많아지지 않게(게시자 정책 "게시자 콘텐츠보다 광고가 더 많음" 항목).
4. **자동 광고:** 앵커와 사이드 레일부터 켜고, 전면 광고는 빈도를 낮게 하고 테스트형 서비스는 URL 제외. 페이지 내 자동 광고는 끄기. **[판단, 기존 계획과 같음]**
5. **신원 확인과 주소 PIN:** 신원 확인 요청이 오면 45일 안에 완료하고 **[공식]**, 수익이 기준 금액(주소 확인 $10 상당)에 이르면 우편 PIN 입력, 이후 은행 계좌와 세금 정보 등록.
6. **정책 센터를 매주 확인:** 특히 칠판, 금융, 건강 페이지. UGC 위반이 생기면 페이지 단위로 광고가 빠지고 반복되면 사이트 단위로 확대됩니다. **[공식]**
7. **개인정보처리방침 갱신:** 애드센스 쿠키와 맞춤 광고, Google 파트너 사이트 데이터 사용 고지를 루트 처리방침에 반영. **[판단]**
