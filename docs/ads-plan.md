## 2. 정책 요약 (근거)

- **팝업·시트**: 사용자가 의도해서 연 창이 아니면 광고를 넣을 수 없다. 팝업 안에도 넣지 않는다. 바텀시트와 모달도 같은 원칙으로 금지한다. [1][2]
- **버튼·탐색 근처**: 링크, 재생·다운로드 버튼, 탐색 요소를 광고 가까이에 두지 않는다. 레이아웃 때문에 생긴 의도치 않은 클릭도 위반이 될 수 있다. 공식 픽셀 기준은 없다. 아래 체크리스트의 150px는 우리 내부 기준이다. [1]
- **라벨**: 「광고」 또는 「스폰서 링크」만 쓸 수 있다. 「추천」, 「관련 링크」는 금지다. [1]
- **클릭 유도·주의 끌기 금지**: 화살표, 애니메이션, 「눌러 주세요」 같은 문구를 쓰지 않는다. 광고를 숨기거나 콘텐츠와 겹치게 해서도 안 된다. [1][9]
- **새로고침**: 사용자가 요청하지 않았는데 페이지나 요소를 새로고침할 수 없다. 타이머로 광고를 다시 불러오는 것도 금지다. [1]
- **콘텐츠 없는 화면**: 오류·완료·종료 화면, 공사 중인 화면에는 광고를 넣지 않는다. 알림, 탐색, 행동 유도에 쓰는 화면도 마찬가지다. [3]
- **광고 > 콘텐츠 금지**: 공백, 헤더·푸터, 링크 목록은 콘텐츠로 치지 않는다. [4]
- **Better Ads(모바일)**: 광고 밀도가 본문 세로 길이의 30%를 넘으면 안 된다. 고정 광고는 한 번만 센다. 프레스티셜, 카운트다운 포스티셜, 전체 화면 스크롤오버도 금지다. 화면의 30%를 넘는 대형 고정 광고 역시 금지다. [5][6][7][8]
- **처음부터 숨긴 슬롯**: 광고 요청이 실행되지 않을 수 있다. family의 ad1처럼 노출한 뒤에 push한다. [10]
- **자동 광고와 수동 광고 함께 쓰기**: 허용된다. 「기존 광고 최적화」를 켜면 Google이 두 가지를 함께 최적화한다. [11]
  - 비네트는 페이지가 바뀔 때(링크 클릭) 뜨는 전체 화면 광고이고, 사용자가 언제든 닫을 수 있다. 빈도를 조절할 수 있다. [11]
  - 기본으로 켜진 「추가 트리거」는 끌 수 있다. 본문 끝에서 5초, 30초 무동작, 탭 전환, 뒤로 가기가 여기에 해당한다. [12]
- **크기**: 300x250은 모바일에서 표준 크기이고, 336x280도 쓸 수 있다. 반응형 레이아웃이면 반응형(`auto`) 단위를 쓴다. [13]
- **SPA 해시 라우트**: 해시 경로가 바뀌어도 새 페이지 로드가 아니다. 이에 관한 공식 문서는 찾지 못했다(미확인). 새로 그려진 `<ins>`만 push하고, 기존 슬롯은 다시 요청하지 않는다. 비네트가 해시 이동에서도 뜨는지는 실제로 테스트해야 한다.

## 3. 자동 광고 설정 (전 사이트 공통)

- **앵커**: 켠다. 「하단만」으로 두고, 1000px 넘는 화면에서는 끈다. 화면을 30% 넘게 가리는 고정 광고는 직접 만들지 않는다.
- **사이드 레일**: 켠다(데스크톱).
- **비네트**:
  - 허브, season, sikdang, names, lotto, lottomap: 켠다. 빈도는 최저로 두고 추가 트리거는 끈다.
  - roots, family, lifeclock, birthyear, market: 처음에는 끈다. 2주간 지표를 본 뒤 결과 페이지에만 실험한다.
- **인페이지(배너·멀티플렉스 자동)**: 처음에는 끈다. 수동 배치를 지키려는 것이다. 나중에 「광고 로드: 낮음」으로 실험한다.
- **제외 페이지**: privacy, terms, contact, about.

퀴즈·테스트 원칙
- 문항 사이에 전면 광고를 넣지 않는다. 직접 만든 인터스티셜이나 결과 보기 전 광고 게이트는 프레스티셜·클릭 유도로 보일 수 있다.
- 광고는 결과가 나온 뒤 긴 스크롤 구간에 몰아 둔다.
- 「결과 보기」, 「다시 하기」, 「공유」, 「이미지 저장」 버튼과 광고 사이에는 텍스트·카드 섹션을 하나 이상 넣는다.

## 5. 하지 말 것

- 모달, 바텀시트, 토스트, 로딩 화면, 빈 결과·오류 화면에 광고를 넣지 않는다.
- 「광고를 보면 결과 공개」 같은 조건을 걸거나, 광고를 클릭하라고 유도하지 않는다.
- 타이머로 광고를 새로고침하거나, 같은 `<ins>`를 다시 push하지 않는다.
- 광고를 자체 추천 카드와 구분하기 어렵게 꾸미지 않는다. 이름을 「추천」으로 붙이는 것도 금지다.
- 직접 만든 고정 배너를 앵커와 함께 쓰지 않는다.

## 6. 엔지니어 체크리스트

- [ ] 슬롯마다 `min-height`로 자리를 미리 잡는다(디스플레이 280px, 멀티플렉스 400px). 레이아웃 이동(CLS)을 막기 위해서다.
- [ ] 슬롯 위에 「광고」 라벨을 붙이고, 앞뒤에 24px 이상 여백을 둔다.
- [ ] 버튼·링크·입력과 광고 사이를 세로 150px 이상 띄운다. 공식 수치가 아닌 내부 기준이다.
- [ ] 슬롯 하나에 push는 한 번만 한다(`data-pushed`, 또는 `ins:not([data-adsbygoogle-status])`).
- [ ] SPA에서 다시 그린 뒤에는 새로 생긴 `<ins>`만 push한다. 같은 결과를 다시 그릴 때는 names처럼 기존 슬롯 노드를 재사용한다.
- [ ] `hidden` 상태에서는 push하지 않는다. 노출한 다음 push한다.
- [ ] 화면 밖 슬롯의 지연 로딩은 공식 허용 문구를 찾지 못했다. 직접 구현하지 말고 기본 동작을 쓴다.
- [ ] 비어 있는 슬롯은 `ins[data-ad-status="unfilled"]{display:none}`으로 접는다. [10]
- [ ] `ads.txt`에 실제 pub ID를 넣는다. 하위 경로 사이트도 루트 도메인 기준으로 적용된다. [14]
- [ ] 배포 전 모바일 360px에서 밀도(광고 높이 합 ÷ 본문 높이 ≤ 30%)를 측정한다.
