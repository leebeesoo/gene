한 줄 결론: **조건부로 하자.** 「소원 종류 × 지역 × 지도 × 가는 길」로 정리한 곳은 아직 없다. 다만 장소마다 글을 직접 써야 해서 v1은 **사찰·자연 바위 위주 약 40곳**, 「이루어준다」가 아니라 **「~로 알려진」**으로 쓰고, 무속 영업장은 뺀다. 올해 수능(11/19)은 놓쳤으니 **새해(12월 중순 공개)**를 목표로 한다.

# 05. 소원 명소 지도 (가칭 「소원길」, `/wish/`)

작성 2026-11-14 · 조사 전용 문서, 사이트 코드는 고치지 않음
표시: **[확인]** 공식·언론 원문에서 확인 / **[추정]** 2차 자료나 내 판단 / **[확인 필요]** 원문을 열지 못했거나 자료끼리 말이 다름

## 1. 무엇을 만드나

- 「소원을 빌면 이루어진다고 **알려진** 곳」을 모아 **지도 + 목록**으로 보여 준다. 고르는 기준은 두 가지: **무슨 소원**(합격·건강·사랑·재물·자녀(출산)·새해 소망) / **어느 지역**(시·도).
- 장소 카드마다: 왜 그렇게 알려졌는지(전설·설화 + 출처), 무엇을 보면 되는지, **가는 길**(카카오맵·네이버지도 버튼), 방문 팁(계단·소요 시간·주차·예절), 사진(라이선스 확인된 것만).
- 우리만의 내용 = 여러 출처를 대조해 **직접 쓴 짧은 글** + 소원 종류 분류 + 「사실 / 전해지는 이야기」 구분 표시. 블로그 글은 베끼지 않는다.

## 2. 검색 수요와 경쟁

**수요 [추정]** — 검색량 숫자는 이 환경에서 볼 수 없다(네이버 데이터랩·키워드 도구는 사장님 계정 필요). 다만 언론이 매년 같은 시기에 같은 주제를 반복하는 것으로 계절성은 분명하다.
- **수능 전 2~4주**: 갓바위 학부모 기도는 매년 기사가 나온다 [확인] (경북매일 2022 https://www.kbmaeil.com/article/202211100347882 , 2026-11 대구교육청 갓바위·성모당 방문 https://www.kbmaeil.com/article/20261110500274 , 「한 가지 소원은 꼭」 기도명당 기사 https://www.news-wa.com/article/travel/tour-korea/2025/11/02/20251102500032 ). 2027학년도 수능은 **2026-11-19** [확인] (https://www.etoday.co.kr/news/view/2390974 ) → 올해는 5일 남아 못 맞춘다.
- **새해(12월 말~1월 초)**: 해돋이 + 소원 기사(향일암·낙산사 등) [확인] (https://m.ohmynews.com/NWS_Web/Mobile/at_pg.aspx?CNTN_CD=A0002390718 , https://www.wikitree.co.kr/articles/1012934 ).
- **부처님오신날(2027년 5월 중순 [확인 필요])**, 시험철(공무원·자격증)은 작은 봉우리 [추정].
- 「연애 소원 명소」는 국내 자료가 적다 [확인] — 수요도 작거나 다른 말(「커플 명소」, 「사랑바위」)로 찾는 것으로 보인다. 사랑 카테고리는 작게 시작.

**누가 상위에 있나 [확인, 검색 결과 기준]**

**「소원」 근거의 등급** (카드에 표시)
- **기록된 전설·설화**: 지자체 안내·백과사전·사찰 공식에 실린 이야기 → 「~라는 이야기가 전합니다」 + 출처.
- **널리 알려진 믿음**: 언론이 여러 해 반복 보도(갓바위 「한 가지 소원」 등) → 「~로 알려져 있습니다」 + 기사 링크 2개 이상.
- **블로그 소문만 있음** → v1에 넣지 않는다.

## 4. 위험

1. **효험 주장**: 「이루어준다」·「합격 보장」 금지. 「~로 알려진」, 「~라는 이야기가 전합니다」만. 페이지마다 한 줄: 「전해지는 이야기를 소개할 뿐, 결과를 약속하지 않습니다.」
2. **종교 중립·예의**: 순위·「기도발 1위」 금지. 불교계 안에서도 동전 던지기 같은 기복 행동을 싫어하는 시각이 있다 [확인: https://brunch.co.kr/@mutate11/830 ] → 「참배 예절」(법당 안 사진, 조용히, 시주함 외 동전 던지지 않기) 칸을 둔다.
   - **사찰·암자, 자연 바위·나무(마을 신앙)**: v1 포함.
   - **성당·순례 성지**: 「소원」이 아니라 「기도·순례 장소」로만, v2에서 검토. 대구 성모당처럼 수능 기도로 보도된 곳만 [확인: 위 경북매일 2026-11].
   - **교회**: 개신교는 「소원 비는 곳」 틀과 맞지 않아 반감 위험 → **넣지 않는다** [판단].
   - **무속 영업장(점집·굿당·신당 영업)**: **제외.** 광고·영업 홍보처럼 보이고 확인도 어렵다. 공공이 관리하는 당산나무·서낭당 같은 민속 문화유산은 포함 가능.
3. **애드센스**: 종교는 게시자 제한·금지 항목에 없다 [확인: 게시자 제한 목록 https://support.google.com/adsense/answer/10437795 — 종교는 「충격적 콘텐츠」 예외 문장에만 등장]. 종교를 이유로 한 혐오만 정책 위반. 위험은 종교가 아니라 **베낀 글·얇은 페이지**(adsense-strategy.md 2장).
4. **블로그 문장 복사**: 금지. 출처 2곳 이상 대조 → 사실만 뽑아 새로 씀 → 출처 링크. AI 초안은 사람이 고쳐 쓴다.
5. **사진 저작권**: 위 표 기준만. 블로그·언론 사진 0장. 3유형은 자르지 않고 비율 유지 축소만. 출처 문구는 사진 바로 아래.
6. **사유지·작은 곳**: 개인 땅의 바위·나무, 수행 중인 작은 암자(일반인 출입 제한)는 넣지 않는다. 「출입 가능 여부 확인일」 칸.
7. **개인정보**: 스님·신도 얼굴 나온 사진 쓰지 않음. 후기·댓글 기능 없음(UGC 관리 부담).
8. **정보가 낡음**: 입장료·주차·통제(산불·공사)는 바뀐다 → 칸마다 「확인일」, 정정 요청은 기존 문의 메일.

## 5. 지도·길찾기

**지금 우리 사이트 방식 [확인, 코드 읽음]**
- 명당로드(`lottomap/app.js`)는 **지도 라이브러리·타일을 쓰지 않는다.** `southkorea-maps`(통계청 2013 경계 단순화본)로 만든 **시·도 SVG**를 직접 그리고, 위경도를 `proj()`로 점 찍는다. 장소 버튼은 `map.naver.com/p/search/이름+주소`, `map.kakao.com/link/map/이름,위도,경도`(좌표 없으면 `?q=`).
- 제철식당(`sikdang/js/util.js`)은 `naverMap()` 검색 링크만.
- → **같은 방식 재사용 권장**: 키·서버·타일 비용 0, 이미 검증됨. 40곳이면 시·도 SVG + 점 + 목록으로 충분.

**길찾기 버튼 (서버 없음)**
| 버튼 | 주소 | 상태 |
|---|---|---|
| 카카오맵 길찾기 | `https://map.kakao.com/link/to/장소이름,위도,경도` (PC·모바일웹 자동, 앱 있으면 앱) | [확인: https://devtalk.kakao.com/t/url-kakao/145970 — 위도·경도 순서 주의] |
| 카카오맵 지도 | `https://map.kakao.com/link/map/장소이름,위도,경도` | [확인: 명당로드에서 사용 중] |
| 네이버지도 | `https://map.naver.com/p/search/장소이름` (검색 → 길찾기 한 번 더) | [확인: 사용 중]. 웹 길찾기 직행 URL(`/p/directions/…`)은 공식 문서 없음 [확인 필요]. 앱 `nmap://route/…`은 `appname` 필수·앱 전용 [확인: https://guide.ncloud-docs.com/docs/maps-url-scheme ] |

- 상세 확대 지도가 꼭 필요하면 v2에 Leaflet + OSM 타일. OSM 공식 타일은 출처 표시·과도한 사용 금지 정책이 있어 트래픽이 커지면 곤란 [추정]. 카카오·네이버 지도 JS는 키·약관 필요 → 쓰지 않음(카카오 JS 키는 당분간 안 받기로 함, HANDOFF).

## 6. 화면·페이지 구성

- **첫 화면 `/wish/`**: 소원 칩(합격·건강·사랑·재물·자녀·새해) + 시·도 SVG 지도 + 카드 목록. 고르면 URL 해시(`#합격/경북`)만 바뀜. 위에 짧은 안내 글(무엇을 모았나, 고른 기준, 「알려진」 원칙, 참배 예절).
- **카드**: 이름 · 지역(시·군) · 장소 유형(사찰/암자/바위/나무) · 소원 태그 · 한 줄 요약 · [사실] 2~3줄 · [전해지는 이야기] 1~2줄 + 출처 · 가는 길(버튼 2개 + 대중교통·주차 한 줄) · 방문 팁(오르막·소요 시간·개방 시간) · 사진 1장 + 출처 · 확인일.
- **SEO 페이지 (정적 생성)**
  - 소원별 6쪽: `/wish/합격/` 「합격 기도로 알려진 곳 n곳」 — 각 쪽에 도입 글 300자 이상 + 카드.
  - 지역별: 장소 **3곳 이상인 시·도만**(약 8~10쪽). 미만이면 만들지 않음.
  - **장소별 쪽은 글이 충분한 곳만**(사실·이야기·가는 길·팁 합쳐 600자 이상 + 출처 2개) — v1 약 12~15쪽. 나머지는 묶음 페이지 앵커.
  - 「수능 기도 명소」, 「새해 소원 명소」 시기 묶음 2쪽(같은 카드 재사용, 도입 글만 새로).
  - JSON-LD: 묶음은 `ItemList`, 장소는 `TouristAttraction`(+`geo`). 순위형 표현 없음.
- **데이터 흐름**: 구글 시트(사람이 쓰는 칸: 요약·이야기·출처·소원 태그·팁·확인일) + GitHub Actions가 TourAPI로 좌표·주소·이용시간·사진(1·3유형만) 채움 → `wish/data/places.json` → `tools/wish/build.mjs`로 정적 페이지. 시트가 정본, API는 보조.
