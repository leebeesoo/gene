# 02. 내 상황 명언 — 최종안 (2026-11-13)

> 서비스 이름 확정: **내 상황 명언** · 한 줄 소개 「지금 필요한 한 줄, 원문과 출처까지」 (이전 가칭 「명언 모음」·「재미랩 명언」). 주소는 그대로 `/quotes/`.

**한 줄 결론: 사장님 생각대로 「묶음 페이지 + 앵커(#) + 검색」을 기본으로 하고, 내용이 충분한 유명 명언만 따로 페이지를 만드는 「섞은 구조」로 가자. 첫 버전은 명언 약 300개, 페이지 약 68개.**

## 최종안 요약
- **본체는 묶음 페이지**: 상황별(졸업·위로…) 12, 인물별 20, 주제별(용기·시간…) 8. 한 페이지에 명언 15~25개를 넣고, 명언마다 `#q123` 앵커를 단다.
- **따로 페이지는 고른 것만**: 원문·출처 검증·배경·비슷한 명언·활용 예를 다 채울 수 있는 유명 명언 15개 + 「진짜 이 사람이 한 말?」 진위 확인 10개 = 25개.
- **검색**: 빌드 때 만든 JSON 하나를 화면에서 바로 검색(서버 없음). 결과는 따로 페이지가 있으면 그곳, 없으면 `묶음 페이지#q123`으로 간다.
- **공유**: 명언마다 글자 카드 PNG를 미리 만들어 두고, 카톡 공유 버튼이 그 카드를 붙여 보낸다. 주소는 `묶음 페이지#q123`이어도 카톡에는 그 명언 카드가 보인다.
- **디자인**: 상황마다 글자 배치 틀이 다르다(위로=부드러운 명조, 졸업=굵고 큰 고딕…). 사진은 묶음 페이지당 1장 이하, 받아서 저장(링크 걸기 금지), 라이선스 기록 필수.
- **페이지 수 걱정**: 페이지 수 자체는 순위 점수가 아니다(일반론). 게다가 도메인 전체로는 다른 서비스 정적 페이지 약 5,700개가 생길 예정이라, 명언 쪽이 70쪽이어도 문제 없다. 얇은 페이지 수백 개가 오히려 위험하다.

## 앵커(#)와 검색엔진
확인된 것
- **# 뒤는 별도 페이지가 아니다.** 구글: "Google Search generally doesn't support URL fragments", 내용을 바꾸는 데 #를 쓰지 말고 History API를 쓰라고 안내([URL 구조](https://developers.google.com/search/docs/crawling-indexing/url-structure), [JS SEO 기본](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)). 인터넷 주소 규칙상 # 뒤는 서버로 보내지 않고 브라우저만 쓴다([RFC 3986 §3.5](https://www.rfc-editor.org/rfc/rfc3986#section-3.5)). → `졸업#q12`, `졸업#q13`은 검색엔진에 전부 「졸업」 한 페이지다.
- **네이버**: 서치어드바이저 공식 문서를 직접 열지 못했다(접속 차단). 위 주소 규칙상 같은 결과로 보고, 00-platform.md도 "해시 URL은 별도 문서로 보지 않는다"로 정리돼 있다. **(네이버 공식 문구는 미확인)**
- **대신 앵커가 검색 결과에 도움이 될 수 있다.** 구글은 검색 결과 설명 안에 페이지 특정 부분으로 가는 「Read more」 링크를 붙이기도 한다. 조건: 내용을 접기·탭 안에 숨기지 말 것, 로딩 때 스크롤을 강제로 옮기지 말 것, 주소의 #를 지우지 말 것([스니펫 문서](https://developers.google.com/search/docs/appearance/snippet)). 자동이라 보장은 없다.
- **추천 스니펫 → 문장 하이라이트**: 구글은 2020년부터 추천 스니펫을 누르면 `#:~:text=` 방식으로 그 문장까지 스크롤·하이라이트한다. 우리가 할 일은 없다. 다만 안 되는 경우도 많다([보도](https://www.seroundtable.com/google-featured-snippets-highlight-answers-web-29557.html)).
- **사이트링크**: 사이트 링크 구조를 보고 자동으로 만든다. 제목·소제목을 짧고 분명하게, 내부 링크를 잘 걸라는 것이 전부([사이트링크](https://developers.google.com/search/docs/appearance/sitelinks)).

긴 묶음 페이지가 여러 검색어에 걸리나
- 구글은 2020-10에 페이지 전체가 아니라 **문단 하나가 검색어에 잘 맞으면 그 페이지를 올려 주는** 「passage ranking」을 발표했다(따로 문단 색인은 없음, 미국 영어부터 적용)([SEL](https://searchengineland.com/google-passage-ranking-347735)). 한국어 적용 범위는 **확인 못 함**.
- 그래서 「졸업 축하 명언 짧은」, 「졸업 카드 문구」, 「졸업식 축사 명언」처럼 비슷한 긴 검색어는 **묶음 페이지 하나로 받는 게 맞다**. 명언 하나만 콕 집는 검색(「니체 나를 죽이지 못하는 것은 원문」)은 따로 페이지가 유리하다 → 섞은 구조의 이유.
- 앵커가 잘 먹히게 하는 방법: 명언마다 소제목 태그(h3)와 고정 id, 페이지 맨 위 목차(진짜 `<a href="#q12">` 링크), 접기 없음.

## 구조 비교(표)
| | (A) 명언마다 1쪽 (수백 쪽) | (B) 묶음 페이지만 + 앵커 (수십 쪽) | (C) 섞은 구조 (추천) |
|---|---|---|---|
| 검색 노출 범위 | 넓어 보이나 대부분 색인 안 될 것(같은 문장이 블로그 수천 곳) | 상황·인물 긴 검색어는 잘 받음. 명언 하나 검색은 약함 | B + 유명 명언·진위 검색까지 |
| 얇은 페이지 위험 | **높음**. 구글 대량 생성 콘텐츠 남용([정책](https://developers.google.com/search/docs/essentials/spam-policies#scaled-content)), 네이버 유사문서, 애드센스 「가치 낮은 콘텐츠」 | 낮음 | 낮음(따로 페이지는 기준 통과분만) |
| 애드센스 | 글이 짧아 광고 1개도 버거움, 도메인 승인까지 위협 | 글이 길어 광고 2~3칸 가능 | B와 같음 + 따로 페이지 1~2칸 |
| 관리 | 매우 큼(쪽마다 고유 글 250자) | 작음 | 중간(따로 페이지 25→80개만 손으로) |
| 사용 편의 | 하나 보고 끝, 돌아다니기 불편 | 비교하며 고르기 좋음(카드 문구 찾는 사람에 맞음) | 둘 다 |
| 공유 | 쪽마다 미리보기 가능 | 미리보기가 묶음 카드로 보임 → 카톡 버튼으로 해결 | 둘 다 |

- **따로 페이지 기준(5가지 모두)**: ① 원문 ② 출처(책·연설·연도·쪽, 검증 상태) ③ 배경 설명 ④ 비슷한 명언·자주 섞이는 말 ⑤ 상황별 활용 예(우리가 쓴 예문). 고유 글 250자 이상. 못 채우면 묶음 페이지의 한 줄로 둔다.
- **겹침 규칙**: 한 명언이 여러 묶음에 들어가도 원문·출처·해설 전체는 「본가」 한 곳에만 쓰고, 나머지 묶음에는 한 줄 + 본가 링크. 묶음마다 고유 소개·활용 팁 250자 이상.
- **오늘의 명언 기록 페이지는 만들지 않는다.** 날짜별 365쪽은 같은 문장 반복이라 얇다. 첫 화면·허브 타일에서 날짜로 JS가 고른다(재빌드 불필요).

## 검색·공유 방식
검색(정적, 무료)
- 빌드 때 `quotes/data/index.json` 생성: `id, 우리말, 원문, 인물, 상황·주제, 이동 주소`. 300개면 약 100KB, 압축 시 약 30KB(추정). 처음 검색창을 누를 때만 받는다.
- 화면 JS로 띄어쓰기 무시·부분 일치·초성 검색(「ㄴㅊ」→니체). 라이브러리 없이 충분하다. 600개 넘으면 MiniSearch 같은 작은 무료 라이브러리 검토.
- 결과 링크: 따로 페이지가 있으면 그 주소, 없으면 `/quotes/for/graduation/#q123`. 도착하면 그 명언을 잠깐 테두리로 표시(스크롤 강제 이동은 브라우저 기본 앵커 동작만).
- `/quotes/search/?q=` 는 noindex. 검색창은 묶음 페이지 위에도 둔다.

명언 하나 공유하기 (# 뒤는 미리보기 로봇도 안 본다 → 주소만으로는 묶음 카드가 뜬다)
1. **카톡 공유 버튼(추천)**: 카카오 JS SDK `Kakao.Share.sendDefault`는 이미지 주소·제목·링크를 우리가 정한다. 명언별 미리 만든 PNG(`/quotes/card/q123.png`) + 링크 `묶음#q123` → **따로 페이지 없이도 카톡에는 그 명언 카드가 보인다.** 앱 키와 도메인 등록 필요([카카오 문서](https://developers.kakao.com/docs/latest/ko/kakaotalk-share/js-link)).
2. **이미지 저장·인스타**: 휴대폰은 Web Share(파일 공유)로 PNG를 바로 넘기고, 안 되면 내려받기. 1080×1350 저장용은 브라우저 캔버스로 그 자리에서 그린다(파일 0개).
3. **링크 복사**: `묶음#q123` 복사. 다른 메신저 미리보기는 묶음 카드(그 페이지 대표 명언)로 보인다 — 받아들인다.
4. **따로 페이지가 있는 명언**: 자기 주소·자기 OG 이미지.
- `?q=123` 방식은 정적 사이트에서 OG가 안 바뀐다(서버가 같은 HTML을 줌). Cloudflare Pages Functions(무료 한도 있음)로 바꿀 수는 있으나 서버 코드가 생기므로 v1은 안 한다.
- (v2 선택) 공유 전용 작은 주소 `/quotes/s/q123/`: noindex·광고 없음·자기 OG, 사람은 바로 `묶음#q123`으로 이동. 검색에 안 나가니 얇은 페이지 문제는 없다고 보지만, 이동 처리가 「속임수 이동」으로 오해받지 않는지 **확인 필요(추정)**.

## 디자인·이미지
상황별 글자 틀 (design-direction.md 규칙: 그라데이션·이모지 금지, 포인트 색 한 곳, 서비스 글꼴 2종 이내 → 카드 이미지 안에서만 틀별 글꼴 허용)

| 크게 | 졸업·합격·새 출발 | 화면 가득 굵은 고딕, 줄마다 크기 다르게 | Black Han Sans |
| 응원 | 수능·시험·새해 | 짧은 한 줄 세로 쌓기 + 큰 날짜·숫자 | Do Hyeon |
| 책 | 인물·고전 | 원문 위·번역 아래, 세리프 조판, 쪽 번호처럼 출처 | Noto Serif KR |
| 축하 | 결혼·생일 | 가운데 정렬, 둥근 고딕, 넉넉한 줄 간격 | Pretendard |

- 페이지 자체도 틀을 따른다: 묶음 페이지 첫 화면에 그 틀로 대표 명언 1개를 크게(`clamp(36px,10vw,88px)`), 아래 목록은 공통 형식.
- 카드 자동 생성: 시트 행 → SVG 틀 → PNG(GitHub Actions에서 무료 `@resvg/resvg-js`). 글자 수에 따라 글자 크기 3단계, 한글은 단어 단위 줄바꿈. 크기: 공유 1200×630(글자는 가운데 1100×560 안, 200KB 이하). 300장 × 약 60KB ≈ 18MB(추정), Cloudflare Pages 파일 수·크기 한도 안.
- 글꼴 파일은 저장소에 두고 라이선스 파일(OFL.txt)을 함께 둔다. OFL은 이미지에 넣어 배포 가능, 글꼴 파일 자체 판매만 금지.

- 시트 「사진」 탭에 `파일 · 원본 주소 · 작가 · 라이선스 · 받은 날 · 화면 캡처 여부` 기록. 사람 얼굴·상표가 보이는 사진은 피한다. 인물 사진은 위키미디어 퍼블릭 도메인 초상만.
- AI 이미지는 쓰지 않는다(이전 검토 그대로: 한글 오류·비용·보호 불가).

시트 칸
- 「명언」: `id(고정, 재사용 금지) · 우리말 · 원문 · 원어 · 인물_id · 출처(책/연설) · 연도 · 쪽/링크 · 검증(확인/전해짐/잘못 알려짐) · 근거 링크 · 상황(여러 개) · 주제(여러 개) · 본가 · 틀 · 따로페이지(Y/N) · 배경 설명 · 활용 예 · 비슷한 명언 id · 공개(Y/N) · 확인한 날`
- 「인물」: `인물_id · 이름 · 원어 이름 · 생년 · 몰년 · 소개 3줄 · 대표 저작 · 사진 파일`
- 「묶음」: `id · 종류 · 이름 · 소개(250자+) · 활용 팁 · 틀 · 몰리는 달`
- 「사진」: 위 라이선스 기록
- 규칙(이전과 같음): 몰년 1962년 이전 아니면 자동 제외, 남의 한국어 번역 금지(우리가 번역), 위키인용집은 원문 찾는 길잡이로만, 가사·대사·현대인 글 제외.

## 사장님 할 일
1. **정하기**: 이 섞은 구조로 갈지, 이름·경로(`/quotes/` 또는 한글 이름), 첫 상황 12개 목록 확인.
2. **구글 시트 1개** 만들기(Claude가 틀 제공) → 탭 4개 「웹에 게시(CSV)」 주소 전달.
3. **출처 확인**: Claude가 후보·원문·출처 초안 300개를 채우면, 사장님은 출처 링크가 진짜인지 확인(하루 30~50개, 1~2주, 추정). 따로 페이지 25개는 해설까지 읽어 보기.
4. **카드 시안 고르기**: Claude가 틀 6종 시안을 보여 주면 고르기.
5. **사진 승인**: Claude가 라이선스 기록과 함께 후보를 올리면 쓸지 말지 결정.
6. **카카오 앱 키**(이미 선택 할 일 목록에 있음): 명언 카드 카톡 공유에 필요. 도메인 정해지면 JS SDK 도메인·링크 도메인 등록.
7. **문의 이메일**: 정정·저작권 신고 창구로도 씀.
